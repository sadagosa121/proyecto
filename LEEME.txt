1. DESCRIPCIÓN DEL PROYECTO
--------------------------------------------------------------------------------
Aplicación interactiva y visual para la simulación del balance energético horario
en una microrred equipada con generación solar fotovoltaica, banco de baterías,
demanda eléctrica y conexión a red externa.

La lógica del modelo calcula hora a hora si se carga la batería, se descarga,
se compra energía a la red o se vierte excedente, manteniendo el estado de carga
(SOC) y evaluando la autosuficiencia energética (% sin red).

3. CÓMO EJECUTAR LA APLICACIÓN
--------------------------------------------------------------------------------
Requisitos: Python 3.10+ y Streamlit instalados.

Paso 1: Abrir la terminal de comandos (PowerShell o CMD) en la carpeta del proyecto:
    cd c:\Users\samue\Downloads\Proyecto

Paso 2 (Opcional - entorno virtual):
    .\.venv\Scripts\activate

Paso 3: Ejecutar la aplicación con Streamlit:
    streamlit run app.py

La aplicación se abrirá automáticamente en tu navegador web en:
    http://localhost:8501

5. RETO FUNCIONAL SELECCIONADO (SECCIÓN 4 DEL PROYECTO)
--------------------------------------------------------------------------------
Se implementó el RETO 2: "Buscar la capacidad mínima de batería para no comprar
a la red en el día", complementado con el RETO 1 (Eficiencia de carga/descarga)
y el RETO 3 (Explicación didáctica de Variable Global vs Return):

- Reto 2 (Capacidad Mínima):
  Función `buscar_capacidad_minima_sin_red(datos)` en `logica.py`.
  Evalúa de manera iterativa el dimensionamiento mínimo del acumulador necesario
  para alcanzar una autosuficiencia del 100% (cero compra a la red). Si la generación
  total del día es menor a la demanda total, avisa que físicamente no es autosuficiente.

- Reto 1 (Eficiencia):
  Función `simular_con_eficiencia(datos, eficiencia)` que incorpora las pérdidas
  reales en los ciclos electroquímicos de carga y descarga.

- Reto 3 (Variable Global vs Return):
  Demuestra por qué en ingeniería es superior el uso de funciones con `return`
  frente a variables globales `global` (modularidad, aislamiento de efectos
  secundarios y testeabilidad).
